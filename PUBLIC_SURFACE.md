# Public Surface

This document defines the intentional public boundary of the `gonzo-max2` GitHub account.

## Public repositories

| Repository | Public purpose | Boundary |
|---|---|---|
| [`gonzo-max2/gonzo-max2`](https://github.com/gonzo-max2/gonzo-max2) | Profile, portfolio site, generated activity, and public-maintenance policy | Presentation and automation only |
| [`gonzo-max2/aegis-unified-0.9.0`](https://github.com/gonzo-max2/aegis-unified-0.9.0) | Open Aegis source, documentation, tests, release evidence, and product interface | Pre-production alpha for one trusted operator; not a hostile multi-tenant security boundary |
| [`gonzo-max2/maya-codex-nexus`](https://github.com/gonzo-max2/maya-codex-nexus) | Sanitized MAYA product case study, public CV, screenshots, and controlled review options | Portfolio showcase, not the private application source |

Everything else owned by the account should be treated as private unless it is deliberately published through a reviewed repository change.

## What “public” includes

Publication is broader than the latest files visible on `main`. It includes:

- Git history, tags, releases, branches, pull requests, issues, comments, and discussions;
- Actions definitions, logs, summaries, caches, and retained artifacts;
- GitHub Pages output, social previews, raw-file URLs, generated assets, and receipts;
- filenames, repository metadata, commit messages, contributor identities, timestamps, and linked external resources;
- copies retained by forks, mirrors, search engines, archives, package indexes, and local clones.

Deleting a file from the current branch does not make previously published content private.

## Publication standard

Public material should satisfy five tests:

1. **Authority** — the account has the right to publish it.
2. **Privacy** — it contains no credentials, private source, customer data, sensitive logs, or accidental metadata.
3. **Evidence** — concrete claims link to the smallest current artifact or check that supports them.
4. **Maturity** — research, prototype, alpha, integrated, released, and independently verified states are not blurred together.
5. **Consistency** — identity, product names, versions, repository links, screenshots, and status language agree across surfaces.

## Deliberately public personal information

The profile brand and any professional information included in the MAYA CV are intentional public disclosures. Additional personal details should not be inferred from private repositories or copied into public automation by default.

## Review cadence

Audit the public surface before each release and at least quarterly. Review repository visibility, profile metadata, pinned repositories, Pages output, generated files, workflow permissions, artifacts, public issues, dependency alerts, and stale claims.
